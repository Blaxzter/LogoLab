# Handoff — §0 #15: a weak colour boundary aims a strong edge

**Status:** diagnosed, NOT fixed. `src/lib/trace/` is untouched by this work.
**Read first:** `docs/vectorization-benchmarks.md` §14 (the full record) and §0 #15 (the row).
**Baseline commit:** `1f6996e`, merged to main as `cdde2d5`.

This file exists so a fresh agent does not re-run the three experiments that already failed.
Everything below is measured, not assumed.

---

## The defect

User-reported from `/labs/gallery` on `affinity-designer.svg`, which the gallery traces
**flat** (`GalleryLab.tsx` hardcodes `gradients: false` — it does NOT auto-choose; the
rampiness auto-probe lives only in `VectorizeStudio`). Flat-tracing ramp art posterizes the
ramp into bands, and each band seam that runs into a real logo edge damages it:

- a straight bar flank **bends**,
- a rounded corner grows **bumps** where the seam meets it.

The banding itself is accepted by the user ("I don't expect a gradient"). What is not
acceptable is the banding moving the logo's real edges.

## What is measured

Contrast per shared edge (ΔE76 between the two regions owning it) is cleanly bimodal — this
is the fact the whole fix rests on:

```
posterization band seams:  ΔE  2.7 – 10.2
real logo edges:           ΔE 47   – 79      (nothing in between; 13 T-junctions)
```

Against the authored path data (`affinity-designer.svg` is 1020 bytes of plain `d`
attributes, so the truth is exact):

| | flat trace | gradients ON |
|---|---|---|
| inner flank, s=6 → s=90 | −0.37 → **+0.61** px (0.98 swing) | −0.35 → −0.27 (**0.08**) |
| triangle apex error | 1.54px | 0.97px |
| inner-panel arc, tangent break both ends | **11.0° / 10.7°** | — |
| outer plate corners (no band junction) | 0.03–0.06 mean, 0.40 swing | — |

The flank does not step, it **rotates** — one fitted edge pinned at two ends carrying
different errors.

## Root cause

A junction is an **integer lattice corner**; the edge it lands on is sub-pixel. Pinning a
116px edge to that corner costs ~1px at that end, against 100+px of its own staircase that
would have placed it far better. The band seam decides where the pin goes, so the **weak
boundary aims the strong edge**.

## Do NOT re-attempt these — all three are measured dead

1. **A flat-authored driver case does not reproduce it.** `band-cross`
   (`public/examples/edge-cases/band-cross.svg`, generated by `genEdgeCases.ts`, registered
   gated tier 0) scores **chamfer 0.14 / p95 0.49 @512 — GREEN**. A weak boundary alone is
   harmless. It is kept as a **control**: a fix that starts damaging flat weak boundaries
   fails the build. Do not delete it, and do not "fix" it to be red without new evidence.
   *Authoring note:* the mark's tightest pair (ΔE 2.7) is unusable — `quantize` merges it
   (§9.7's veto only protects ≥ ΔE 4), so the band vanishes and the case goes red for an
   unrelated reason (measured: 4 fills instead of 5, p95 25.7px).

2. **Neither a ramp version nor sub-pixel phase reproduces it.** `bandCrossProbe.ts` builds
   the same geometry over a linear ramp and sweeps 10 sub-pixel phases against a
   **no-bands control**: worst flank deviation `none 0.82 / bands 0.83 / ramp 0.94`. The
   control reaches the same magnitude. Whatever the extra ingredient in the real mark is, it
   is not "bands crossing a bar" and not phase alone. **Finding it is open work.**

3. **A post-fit contrast-ranked re-seat in `planarBeautify` CANNOT work.** This was built in
   full: per-edge contrast from the shared-edge graph, a sibling pass to `reseatJunctions`
   gated on the ΔE split. It identified the junction correctly
   (`ends=3 de=[2.7,50.5,52.3]`, strong=2, weak=1, continuation confirmed) and then moved it
   **0.000px**. The primitive is fitted from the *already-pinned* edge — the 99px flank is a
   single straight fitted segment ending at the vertex, so its line passes through the vertex
   by construction and projecting onto it is a no-op. By the time beautify runs, the tilt is
   baked in and the correcting evidence is gone. The code was reverted, not shipped.

   Two sub-results worth keeping if the pass is ever rebuilt elsewhere:
   - comparing the two arms' **fitted lines** fails — a 17px arm's direction is noise;
   - a **tight corridor** around the primitive is circular — the stretch being corrected is
     itself displaced, so it sits outside its own line;
   - a **chord-direction test at 15°** does work (a real corner turns ≥30°, a 20px chord has
     ~3° of noise).

## Where the fix has to live

`assemblePlanar` (`src/lib/trace/planarAssemble.ts`), which still holds each edge's raw
lattice chain in `net.edges[].pts` — the evidence the pin destroys.

Shape of it: where a **weak** boundary ends on a **strong** one that continues through, fit
the strong boundary **through** the junction as one chain, then split the fitted curve at the
junction's projected position. The strong edge is then placed by its own 100+px of staircase
and the weak arm's endpoint follows. Both regions still reference one shared edge, so the
planar invariant (byte-coincident boundaries) is untouched.

Supporting evidence this is the right direction: with gradients ON, where the same flank has
no band junction cutting it, the trace lands at a uniform −0.30px with **0.08px** of swing.
Removing the pin recovers that.

```
src/devtest/bandPullRender.ts    source | variant crops at zoom, for looking at it.
                                 --crop x,y,w,h --zoom N --variants base,reseat-off,grad
src/devtest/bandCrossProbe.ts    the flat-vs-ramp-vs-none phase sweep (experiment 2 above).
```

**Two measurement traps, both hit during the diagnosis:**
- Scan the rendered boundary with **bilinear** sampling. Nearest-neighbour quantizes the scan
  and turns a gradual tilt into a fake step — which points at a completely different
  mechanism (local label flip instead of a pinned rotation).
- When sampling "the boundary near an authored line", filter to **high-contrast edges only**
  and exclude the **canvas border**. A band edge leaving the junction and the white
  background's own border loop both sit inside a naive corridor and produce bogus 3–4px
  readings.

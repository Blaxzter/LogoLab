What this page is, and how to read each panel

Every case in GOLDEN_CORPUS, rendered. The regression suite asserts numbers against test/golden/trace-baseline.json; this page shows the pictures behind those numbers, and how much room each gate has left before it fails. The case list and trace options are imported from the same module the Node gate uses (src/devtest/traceCorpus.ts), and the metrics come from the same scoreDoc() the gate calls — so what you see is what CI measures. Drag any box to pan, wheel to zoom; every box moves together, so you can inspect one detail across source, render and error map at the same framing. Read-only: nothing here re-blesses anything.

This page measures drift, not correctness. Every number is relative to the tracer's own last-blessed output, so a case can sit at 100% headroom while being wrong — bloom passes every gate here and still drops two of its seven regions. For "is it correct", see ground truth, which scores against the authored SVG instead.

source — the pixels the tracer is handed, after the corpus's box-downscale.
current trace — the live vector output (SVG). Toggle nodes/edges to see the shared-edge graph whose counts are gated: ▪ corner ● smooth ◎ junction.
rasterizeDoc render — the trace rasterized. This, not the SVG, is what every fidelity metric is computed against.
ΔE error map — per-pixel CIE76 ΔE between source and render. 0 → scale. ΔE ≈ 2.3 is the just-noticeable threshold, so anything green-and-up is visible.
seam map — only the pixels the seamMax gate actually scores (a traced boundary that is NOT a correctly-reproduced edge). ✚ marks the single worst pixel — that one pixel is the gated seamMax.
headroom — how much of a gate's allowance is still unused. 100% = sitting exactly on the golden; 0% = about to fail. A gate that never leaves 100% is not doing any work.
